# UPSP 0.1.0-alpha.7｜自动缓存、实时审批与长任务稳定性更新

Alpha 7 集中收口 Alpha 6 发布后在真实长任务中暴露的问题：缓存策略不再需要用户手工选择，副作用工具可以直接在对话中实时审批，任务续轮、API 恢复、重试预算和桌面状态判断也完成了一轮系统性修复。

本版本没有增加新的理论层或产品代际，重点是让现有 Seed Runtime 更稳定、更可控，也更容易回看真实运行证据。

## 缓存改为隐藏的自动能力

- 删除 GUI 中的缓存策略选择器，所有模型配置统一使用 `automatic_tiered`。
- 固定协议层作为稳定缓存前缀，并按当前最近层／周期层自动建立第二级缓存边界。
- OpenAI Chat、OpenAI Responses 和 Anthropic Messages 共用同一套分层语义，再按各自协议编译请求字段。
- 旧的 `off`、`key_only` 和 GPT-5.6 专用配置会自动迁移，不影响其他模型参数。
- 审计分别记录缓存规划、实际请求格式、前缀指纹和 provider 返回的缓存 token，不把“发送了缓存字段”误报成“已经命中”。

真实长任务中，相同 B1 前缀指纹多次获得 `4608 cached tokens`；同一指纹也偶尔被 provider 返回为 0，因此本版本不承诺固定命中率，后续仍会继续优化长前缀的实际复用效果。

## 三档执行权限与对话内实时审批

- **只读**：仅开放文件读取、搜索和网页读取工具。
- **受限**：默认档位。读取直接执行，写文件、修改文件、运行命令和派发子代理前，在当前对话中显示审批卡。
- **放行**：完整开放已启用工具，不逐次弹出审批。

受限档审批只提供“跳过”和“本次允许”。一次允许只对应当前精确调用，参数变化会重新审批；本版本不增加永久白名单或工作区配置。

无额外工程 sandbox 配置时，可访问 Windows 当前用户本来有权访问的普通本机路径；位格真源、凭据位置、Git 内部路径和灾难性命令仍保留硬边界。

## 任务引导与错误反馈闭环

- 历史任务和旧 guide 继续保留在上下文中，但明确标记为不可执行；只有当前活动任务坐标可以提交。
- 误用旧 guide、错误任务坐标、来源校验失败或工具被拒绝时，会返回结构化原因和明确订正动作。
- 项目根目录可以由实际读过的后代文件满足来源校验；账本仍只记录真正读取的文件。
- 连续重复同一终止阻断时会本地收束，避免模型反复生成大段自然语言或无限调用。

## API 降级恢复与 Runtime 稳定性

- 处于 `api_degraded` 时，Runtime 会在建立 Round 和执行 Setup 前沿当前路由链进行最小恢复探测。
- 任一 Setup 候选恢复后，先清除降级状态，再重新判断是否需要开轮；探针不会装配位格、上下文、工具或缓存。
- 自动续轮显式继承当前执行权限；新用户消息可以覆盖，桌面进程重启后安全回落为“受限”。
- 无真实进展的 relay 最多允许一次；再次空转会本地停止。
- 每个路由槽只保留一份“首次加两次暂态重试”预算，上层不能重复刷新预算。
- 未收到协议终止事件的 partial SSE 只进入审计，不再冒充完成回复。
- 每次启动都会重新计算待命轮倒计时，停机时间不计入等待时间。

## 缓存身份与用户输入保护

- 活跃语料的短 ID 只在首次进入当前缓存时分配，跨 Frame、进程重启和 `now → lately` 移动时保持稳定。
- 只有压缩后产生的新语料才会获得新 ID。
- 用户原始输入进入最近缓存后，在连续 16 个交互轮内不得被删除或压缩；第 17 个交互轮起恢复普通 FIFO 资格。
- 该保护只覆盖用户输入，不会把整个 Round、回复或工具结果永久留在高频层。

## GUI 可用性修复

- 同一轮用户消息只显示一次，不再因多个 Frame 重复生成用户卡。
- 任务建立、更新和完成会随 Runtime 事件及时刷新。
- “任务与证据”新增 Round／Frame 回看入口，可以查看历史帧当时真正装配的任务清单及该帧工具、结果和回执证据。
- live JSONL 改为增量读取，不再每 500ms 重读整份运行账本。
- 桌面健康检查改为单请求执行；单次后端繁忙只显示非模态提示，不再误报“后端已经死亡”。

## 真实长任务验证

本版本完成了一轮 12 项 Agent 日常能力测试：读取任务材料、核验官方来源、实际生成 16 个输出文件并重新执行两个 Python 产物。任务项和验收项均以真实 evidence refs 结算，最终回复非空，活动任务正常退出。

该轮 16 次 provider 请求全部返回 HTTP 200；后续独立节律轮在一次 TLS 暂态重试后于既定预算内恢复并闭合，没有形成新的空转续轮。同一用户消息只显示一次，同一活跃语料短 ID 保持稳定，并获得了上述非零缓存命中证据。

## 升级与数据边界

- 可以从 Alpha 6 直接覆盖安装 Alpha 7；程序、位格数据和本机设置仍然分开保存。
- 旧缓存配置会自动迁移为统一自动策略。
- 默认执行权限改为“受限”；重新启动桌面程序后不会恢复此前的“放行”选择。
- 实时审批的完整命令、补丁和文件正文只在当前进程中瞬时保存；长期审计只记录安全摘要和审批结果。
- 历史任务回看只覆盖本机仍保留的 Round FIFO，不会伪造已经淘汰的历史快照。
- 本版本不会删除既有任务历史、记忆、关系或工作容器。

## 当前阶段边界

- 仅提供 Windows x64 桌面版；
- 当前只有一个活动位格和一条主对话线程；
- Arbor 器官协作、分身、多位格协作和自动更新尚未实现；
- 安装器尚未签名，Windows 可能显示安全提醒；
- 模型服务继续采用 BYOK；
- 实际缓存命中仍受 provider、模型、路由和前缀稳定性影响；
- 实时审批暂不提供永久白名单或工作区管理。
