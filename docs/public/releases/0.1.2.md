# UPSP 0.1.2｜对话时间线、任务续做与运行稳定性更新

> Windows x64 · Base / Seed · 正式版0.1.2。安装器未签名；升级前请备份数据与本机配置。

0.1.1 建立了多位格与分身、LTM 记忆真源和长程上下文的基础。0.1.2 沿着实际使用中暴露的问题继续往下修：对话里分清模型正在做什么，长轮运行时界面不再被审计数据拖住，任务计划可以随现实修订，意外退出后也能先核对已经发生的动作，再决定怎样继续。

这一版仍是 Windows 桌面端的 Base / Seed，没有引入向量数据库、云端记忆服务或新的多 Agent 调度层。

## 对话窗口：按真实发生顺序展示一整轮

- 起手、反应、善后的思考片段、自然语言进展、工具调用、审批、最终回复和失败状态，按实际事件顺序排列。
- 只有模型服务明确提供的推理内容才显示为思考片段。不从自然语言风格猜“它正在思考”，也不为不公开推理的模型补造思考文本。
- 一轮可以有多个独立思考片段，与工具和进展交错。活动片段自动展开，后续事件出现后收起；手动展开或收起的选择不会被轮询重置。
- 每个工具都有自己的执行节点，参数与结果分别查看。成功、失败、审批、跳过和停止都有文字状态，不再挤进一个总折叠框。
- 增加呼吸环与整轮计时，显示当前阶段。最终回复之后仍可能有善后事件；界面不把“回复生成完了”伪装成“本地结算已经结束”。
- 修复推理通道被重复当作轮中进展写入的问题，以及合法成功回执被显示成失败、累计回执被重复投影等问题。
- 旧轮保留原有卡片和审计内容，不把缺少事件坐标的历史猜成新版时间线。

## 流式、贴底与分栏

- 自然语言输出使用短语平滑释放，缓和成批到达时的跳字；结束、停止或错误时及时显示已确认的剩余正文。
- 正文只增量更新当前节点，结算后转为 Markdown，减少整段对话反复重建。
- 用户停在底部时，思考、工具、新回复和 Markdown 展开会继续跟随；主动上翻后保留阅读位置，重新拉到底才恢复跟随。
- 系统窗默认与对话区各占约一半。桌面端可以拖动分隔条、键盘调整或双击复位；比例保存在本机，窄屏仍使用全屏系统窗。
- 本地结算期间保留黄色停止按钮，但明确禁用；宿主真正回到空闲后恢复发送，减少“轮已完成却还不能操作”的误导。
- 字体随程序打包，首屏不再等待外部字体；动效遵守系统的减弱动画偏好。

## 长轮与历史审阅：需要时才读详情

- 聊天首屏只读取轻量时间线和 Frame 目录，不再顺带生成整轮上下文、完整请求和大型工具结果。
- 打开某个 Frame 或工具节点时，才加载其上下文或参数结果；协议中心、任务证据和导出功能继续保留。
- 流式事件中重复的相邻坐标在界面投影里无损折叠。文本、顺序和工具边界不变，原始 Round 审计不改写。
- 时间线暂时不可用时，只在对话区提示并重试，不再把仍在运行的 Runtime 误标为离线；停止和审批继续依据宿主真实状态工作。
- 启动和切换身份先显示应用壳及加载状态，不让整窗等待巨型历史投影。

## 任务计划可以修订，完成仍要有证据

- 任务清单明确是一份可修订的工作计划。计划中的来源路径可以先登记，不再要求为了“允许写计划”提前完成所有读取。
- 初始任务建账可以与其他合法工具同帧提交，删除无关调用之间的机械互斥。
- 新输入改变工作要求时，可以修订目标片段；修订保留差异记录、已经完成的项及其证据，不能靠重写计划抹掉完成历史。
- 写文件、运行命令、任务完成与验收仍需真实回执。计划来源坐标本身不算读取证据，也不能证明完成。
- 修复临时门禁拒绝被缓存成整轮永久失败的问题。指南、权限或单帧预算变化后会重新裁决；已经成功的副作用仍防止重复执行。

## 退役焦点体系，统一常驻正文

- 移除旧的容器焦点和单帧单焦点限制；工具按读取、修改位格内环境、操作宿主或外部环境区分。
- 记忆条目、容器目标文件和关系卡正文统一通过常驻清单保存引用。每帧读取当前真源，不维护另一份可能过期的正文快照。
- 起手、反应、善后三步均能看到跨轮常驻正文；只有反应循环叠加本轮临时挂载，并执行记忆召回、修复 STM、加热等生命周期。
- 多个已可见容器可以分别续写。刚在同帧读取或创建的容器，需要下一帧真正进入模型输入后才能续写，避免未读正文就改写。
- 关系摘要继续属于状态栏，与关系正文的常驻分开。编年史参考内容改为当帧资料，成功提交后才一次性写出终稿，不预留半成品正文。
- 修复未来容器读取错用路径及目标文件错配；未来、项目、辩证链、事件链等工作数据在各分身创建后独立演进，不持续共享。
- 删除旧工具分类兼容层、记忆注释残链和重复挂载状态；当前工具清单只以本帧原生工具头为准。

## 记忆与感受结算归回反应循环

- 真正进入反应循环时，才结算到期感受脉冲及本轮一次自然回落；待命、起手拒绝或必需上下文失败不消耗这次内部代谢。
- 成功写入记忆条目后的直接感受在当前 Frame 结算，包含即时重写指南最终写入的条目。
- 正常最终回复、可审计的阻塞终态和合法中继，统一推进热度、STM 遗忘、自然入库和联想计数；用户停止或模型服务致命失败不伪装成正常代谢终态。
- 善后保留缓存迁移、压缩债务、旗标、节律收尾和审计，不再重复处理记忆与感受生命周期。

## Windows 命令执行与意外中断续做

- Windows Shell 后端显式使用 `cmd.exe`，不再依赖 Python 的隐式 Shell 包装。工具头标明方言；PowerShell 需显式调用，多行命令会在执行前拒绝。
- 安装包构建必须通过实际 payload Shell 检查，包括嵌套 cmd、PowerShell、中文与空格目录、标准输出/错误分离和非零退出码。
- 文件写入、编辑、Shell 和子代理动作在副作用前登记。文件记录写前与候选 SHA，写入使用同目录暂存、刷盘、原子替换和读回核验。
- 意外退出后，启动只核对现场，不自动调用模型、重跑命令或回滚旧正文。文件可以按当前字节识别是否已落盘；已经启动但没有结果的 Shell 只能记为“结果不确定”。
- 用户发起继续后，恢复事实进入原任务的待整合输入；没有活动任务时，只提供一次当帧恢复资料，不强迫另建恢复任务。
- 已证明成功的同签名动作不会重复执行；冲突或未知结果不会被当作成功。后续工作需要新的合法动作和真实核验。

这不是保存 Python 调用栈或模型会话的断点续传，也不保证任意外部副作用恰好执行一次。系统不保存完整文件备份，不提供通用撤销；重要资料仍需用户自己的备份。

## 已有真实验证与本版验收口径

本次更新前完成了一场真实硬退恢复测试：摘要已落盘、核验 Shell 已启动且没有结果时强制退出程序，同根重启后由用户请求继续。

- 已落盘摘要保持不变，重启没有调用模型或重放动作。
- 原核验结果保持未知；模型取得新核验的真实成功后才写入回执，5个任务项、4个验收项完成。
- 两轮共18次模型调用，HTTP均为200，无传输重试；输入726,367、缓存读取584,192、输出59,371 Token，加权缓存读取比例80.43%。
- 固定环境为 DeepSeek-v4-flash/high、官方线路、100万上下文、Windows。这是一场恢复测试，不是缓存 benchmark，也不证明其他任务或模型必然达到相同比例。

本版候选的唯一一次全量测试为3175通过、1项旧版本断言失败；修正后，该项与相邻About测试均通过，没有把定向补验冒充第二次全量。前端检查、DDS truth、活动范围一致性、安装包Shell检查及隔离启动通过；旧0.1.1数据副本完成升级，所核验的身份与正文文件保持不变，二次初始化幂等。既有测试文件体量治理债务仍保留，未执行真实UAC覆盖安装。历史 LoCoMo 与12任务成绩不作为本版重新测得的性能承诺。

## 升级前与已知边界

- 升级前请备份 `文档\UPSP\` 与 `LocalAppData\UPSP\config\`。程序、位格数据和本机模型配置继续分离。
- 旧数据仅按可证明的已知形状迁移；未知或冲突不会被新默认值覆盖。数据副本启动验收不等于在用户机器完成了提权覆盖安装。
- Windows安装器仍未签名；请只下载正式 Release 附件并核对 SHA-256。没有自动更新、云同步或遥测。
- 仍只允许一个活动位格/分身；不支持并行分身、合并、项目自动绑定、Arbor器官调度、记忆条目私密访问域或模型自动定期挂载。
- Shell运行在当前宿主用户权限下，不是完整操作系统沙箱；工具权限与数据边界仍需按任务选择。
