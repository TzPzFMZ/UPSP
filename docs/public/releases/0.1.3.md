# UPSP 0.1.3｜故障恢复、上下文审阅与升级可靠性更新

> Windows x64 · Base / Seed · 正式版 0.1.3。安装器未签名。

0.1.3 集中改善长任务运行中的可靠性：工具出错时留下准确结果，写入中断后保留恢复依据，查看历史时看到当时的上下文，安装更新失败时能够核对并恢复旧程序。

## 工具出错后，已经完成的结果仍然保留

- 搜索结果中的坏链接按项剔除并记录原因，不再因为一个候选地址异常使整次搜索崩溃。网络解析、响应截断和非法文件编码等预期错误返回明确的失败或拒绝结果。
- 批量工具依次执行，每项结果完成登记和必需上下文投影后才继续下一项。后项失败时，前项已完成的工作、回执和行动记录保留；未执行的请求不会被标成已完成。
- 修正子代理工具的数组参数处理，以及自定义执行器内部报错后可能被再次调用的问题。
- 模型持续输出正文或推理、触发本地输出上限时，显示对应的停止原因和技术详情，便于区分输出上限保护与模型服务故障。

## 写入与恢复：把未确认的状态留在现场

- 加强记忆条目、容器、关系、编年史、任务、缓存压缩及配置更新的写入和回滚边界。写后登记失败或回滚未能核验时，保留原始异常、受影响对象和已有回执。
- 后续结算再次失败，也不会覆盖前一次故障的恢复依据。配置更新与关轮同时登记时，两方故障信息都能保留。
- 启动时检查当前分身行动账本中的遗留事项，包括历史轮已经关闭但行动仍未登记完整的情况。重复启动只核对和分类，不自动重跑 Shell 或其他副作用。
- 模型目录更新若无法确认恢复，界面显示恢复状态并阻断后续写入；读取、停止和退出入口继续保留。重启不再被当作问题已经解决。
- 收拢已知旧配置的迁移入口，先确认目标写入，再清理旧来源。损坏或未知格式明确报告，避免被空数据或默认值掩盖。

## 上下文与历史：保持当时的记录

- Frame 详情与证据导出只使用该帧已记录的上下文。之后变化的活动正文、任务状态或窗口数值，不再覆盖历史帧；最新帧同样遵守这一规则。
- 分层上下文的状态栏增加当前分身标识及分身／轮号坐标，便于区分不同分身中的运行记录。
- 修正技能关联的悬空检测、轮起点和时区计算，以及问题解除后旧警告未撤销的情况。
- 修复旧轮日志缺少末尾换行时，后续事件可能与原记录拼接的问题。读取失败保留错误信息，不当作没有历史。

## 界面与桌面：避免旧响应和未知结果误导操作

- 切换详情、语言或宿主会话时，使旧请求和旧缓存失效，减少先前响应覆盖新选择的问题。文档关闭后释放相关正文与渲染缓存。
- 区分合法空内容、读取失败、旧快照和提交结果未确认。提交响应丢失后先回查；带宿主会话和请求标识的重复提交受到去重保护。
- 加强桌面启动握手和退出处理。连接断开或等待超时，不直接等同于操作没有发生或进程已经退出。

## 安装与更新

- 构建在独立目录完成，记录实际源码状态、依赖与载荷哈希；只有构建和校验完成，才生成可交付候选。
- 更新前先准备并校验完整新载荷，替换前保留可恢复的旧程序副本；新文件核验通过后再登记成功、更新快捷方式和清理。
- 替换或恢复失败时保留明确的恢复记录，避免误报安装成功。程序替换不包含位格数据和本机模型配置。

本版仍使用手动下载安装器的更新方式，安装器未签名。升级前建议备份 `文档\UPSP\` 和 `LocalAppData\UPSP\config\`；使用自定义数据目录时备份对应位置。

本版仍是单个活动位格／分身的 Base / Seed。没有新增多分身并行运行、分支合并或 Arbor 调度能力。恢复依据用于核对已发生的动作，不等同于任意外部操作都能自动撤销或无损续跑。
