# UPSP 0.1.0-alpha.8｜上下文真源、请求差分与长任务闭环更新

Alpha 8 集中解决 Alpha 7 之后在上下文审阅、模型配置和真实长任务中继续暴露的问题：现在可以直接查看每个 Frame 的上下文用量和十层内部边界，沿实际 HTTP 请求字节定位相邻调用从哪里开始变化；任务引导、网页读取、阻塞结算、网络重试和桌面健康判断也完成了一轮根因级修复。

本版本没有增加新的理论层或产品代际。重点仍是把 Seed Runtime 已有能力做实：模型实际看到了什么、请求实际发出了什么、任务为何继续或停止，都尽量回到同一份后端真源和可复核证据。

## 单帧上下文用量与十层分块审阅

- 对话输入区增加上下文占用圆环；悬停可查看当前 Frame、字符数、输入 Tokens、识别容量和 Runtime 运行上限。
- 上下文审阅会显示所选 Frame 的完整字符数、provider 返回的输入 Token 数和调用编译时间。
- Token 数只使用 provider 的真实回执，不在浏览器里估算；新回执返回前继续显示上一条已确认数据，不再反复闪烁“计算中”。
- Anthropic 的普通输入、缓存创建输入和缓存读取输入会按完整口径合计；OpenAI、Responses 和 DeepSeek 继续使用各自真实用量字段。
- 模型的“识别容量”和用户可编辑的“运行上限”正式分开。已知容量时禁止把上限填得更大，未知模型仍可手工配置。
- `30_lately` 和 `50_now` 按真实语料块显示；其余可分层内容按组装器掌握的规则、记忆、状态、任务、挂载和提醒模块显示，不再由前端猜 Markdown 标题。
- 旧 Frame 不会被伪造回填；缺少结构化边界时仍以完整层单卡显示。

## 时间真源与动态记忆投影

- 上下文审阅显示 Frame 的完整本地日期和秒；语料卡显示其持久化时间，而不是页面打开时间。
- 模型可见语料头与 GUI 使用同一份时间真源，缺失或非法时间不会被浏览器当前时间补齐。
- 公共记忆的入库时间、最近调用轮次与时间、当前挂接备注、备注更新时间和关联容器改为从最新元数据统一投影。
- 已挂载记忆在下一 Frame 直接读取最新备注和容器关系，无需先取消再重新挂载；物理正文中的旧动态字段不再覆盖当前元数据。
- 最近调用时间只提供时间上下文和召回轨迹，不承担记忆是否过时的裁决。

## Wire 请求真源与前缀差分游标

- 请求体 SHA-256 和 HTTP POST 现在严格消费同一组 canonical UTF-8 JSON 字节；发送前发现字节不一致会直接阻断。
- 新 Frame 会在发送体外保存 Wire SHA、字节数和来源映射，不改变 provider 实际收到的协议字段。
- 上下文审阅新增窄差分轨道：三角游标标出当前 Frame 相对最近兼容 Frame 的最长公共请求前缀终点。
- 点击游标会切换到对应层并跳到右侧块或块间缝隙，可直接看到从哪里开始成为变化后缀。
- 差分只比较相同连接、模型、协议形状、缓存键和调用 lane 的最近兼容 Frame，避免把物理相邻但不兼容的 Setup、Reaction、Cleanup 或备用路由混在一起。
- 该功能证明的是本机实际请求字节从哪里开始变化，不等同于 provider 最终采用的缓存断点，也不承诺缓存命中率。
- 上下文目录的字符数统一为模型可见正文，不再把审计 JSON 包装误算成缓存正文；水位晋升也不会再被误标为整段替换。

## 模型连接与配置保存

- 模型服务的请求路径会按协议给出默认值，但现在可以直接编辑覆盖，适配使用非标准路径的兼容服务。
- 保存模型能力档位时，三阶段主模型与备用路由会在同一事务中迁移到仍然有效的档位。
- 保存失败时不再整页重绘并弹回旧配置；当前草稿会留在表单中，用户可以直接订正。
- API 降级恢复探针不会再携带正常推理所用的显式缓存字段，避免最小探针因缺少上下文层而在本机误失败。
- 运行中的 Setup／Reaction 允许切换“只读／受限／放行”；新选择从下一 Frame 生效，不追溯放行正在等待的工具调用，Cleanup 期间仍禁止更改。

## 结构化纠错与任务阻塞收束

- `guide_submit` 的校验错误现在直接在 processor 源头生成结构化提示，明确给出尝试值、当前合法状态、预期坐标和下一步订正动作。
- 工具结果、对话 POPUP 和审计消费同一份提示，不再各自根据错误字符串猜一套解释。
- 任务建账前后都受同一纠错止损保护；连续第三个 provider Frame 仍只产生拒绝时会在本地阻断第四次 Reaction 调用。
- `blocked` 任务项必须同时具有原因和真实证据引用。失败工具调用可以作为阻塞事实，但不能冒充完成或验收通过证据。
- 当全部必需项都已经有成功或阻塞证据，且至少一项阻塞时，Runtime 会识别为终态阻塞；即使模型仍请求 `continue`，也不会再创建 relay。
- 阻塞终态仍会正常调用一次 Cleanup provider，让模型完成善后总结；只有 Cleanup 本身失败时才回退到本地应急结算。

## 网页续读、安全与网络恢复

- `has_more` 现在只表示当前抽取正文确实存在下一字符窗口；“源站响应可能被截断”不再伪装成可继续游标。
- 续读游标绑定抽取正文 SHA-256。网页内容变化时返回 `source_changed`，不会拿旧坐标读取新正文。
- `find_text` 可以在当前正文中进行大小写不敏感的字面定位，命中后返回有界窗口；未命中时会明确保留“源可能不完整”的限制。
- 网页读取会在初始地址、每次重定向和最终地址上检查 DNS 与目标 IP；私网、回环、链路本地、保留地址和解析失败均 fail closed。
- provider worker 会把连接重置等暂态网络错误完整传回 Runtime，并继续使用原 Frame 的既有重试预算；上层不能再重新发放一套预算。

## Runtime 与桌面健康修复

- `/api/runtime/status` 不再在 GUI 的高频轮询中扫描完整 Round JSONL 或调用 CLI 全账状态，长账本运行时显著减少后台阻塞。
- 桌面程序只在确认后端进程已经退出时显示故障弹窗；进程仍存活时的单次或连续超时只显示非模态“后端繁忙，正在重试”。
- blocked、provider failure、用户停止和正常完成继续保持各自独立的结算语义，不再用空回复或伪正常闭合掩盖失败。
- 恢复工具会同时核验事故归档清单和当前位格、狗粮目录、Runtime 作用域，允许安全续跑已经完成一部分的恢复，也会拒绝无法解释的第三种漂移状态。

## DeepSeek 官方 API 真实长任务验证

修复后使用 DeepSeek 官方 API、`deepseek-v4-flash` 和 OpenAI Responses 兼容协议完成了一轮 12 项 Agent 日常能力测试：

- 12/12 任务项完成，3/3 验收项通过；
- 16/16 个产物存在且非空，两个 Python 产物均实际执行并返回 exit code 0；
- Runtime 工具事务审计为 `ok`，最终回复非空，Cleanup provider 恰好调用一次，活动任务正常退出；
- 39 个 logical call、40 次 HTTP attempt；唯一一次流式空闲超时在同一调用的既有预算内恢复，最终没有 503 或终局 `llm_error`；
- provider 回报输入 5,453,398 Tokens，其中缓存读取 4,650,240 Tokens，加权读取命中率为 85.27%；39 个 logical call 均返回非零缓存读取；
- provider 没有返回 cache-write tokens，因此这里只报告读取命中，不推断缓存写入量；
- 本轮及随后四个待命轮均没有 `memory_write` 回执或 `MEM-*` 产物，不把普通状态衰减冒充记忆写入。

这些数字是本次特定模型、协议、路由和前缀下的真实回执，不构成其他 provider 或任务的固定性能承诺。

## 升级与历史数据边界

- 可以从 Alpha 7 直接覆盖安装 Alpha 8；程序、位格数据和本机模型配置继续分开保存。
- 本版本不会删除既有任务、记忆、关系或工作容器。
- 新的时间、分块、Wire SHA 和来源映射只对具备对应审计合同的新 Frame 提供精确能力；旧 Frame 不回填、不按 Markdown 或当前配置猜测。
- 已保存的模型连接继续保留；自定义请求路径作为连接 URL 的一部分保存。
- 运行中的“放行”仍不会在桌面进程重启后自动恢复，重启后安全回落为“受限”。

## 当前阶段边界

- 仅提供 Windows x64 桌面版；
- 当前只有一个活动位格和一条主对话线程；
- Arbor 器官协作、分身、多位格协作和自动更新尚未实现；
- 安装器尚未签名，Windows 可能显示安全提醒；
- 模型服务继续采用 BYOK；
- 上下文 Token 只显示 provider 回执，不估算尚未发送的输入或缺失的历史用量；
- 请求前缀差分只证明本地 Wire 字节变化，不证明 provider 缓存实现；
- 网页抽取能力仍受目标网站公开可达性、页面结构和抓取后端限制；
- 实时审批暂不提供永久白名单或工作区管理。
