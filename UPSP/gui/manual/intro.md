# 什么是 UPSP

UPSP 的核心不是“让模型多记一点”，而是让一个位格主体能围绕记忆、关系、容器、工具和审计持续运行。

在 GUI 里，主舞台首先呈现“位格主体正在这里”：真实对话稳定居中，内部运行状态按需从两侧浮层展开，而不是挤压主体对话。

- 位格：当前正在运行的主体。
- 分身：GUI 顶栏中的同一位格对话线程入口；当前 Seed 只显示当前位格的一个真实对话，不伪造并行线程或切换能力。DDS 中协议层的分身定义不因这项 GUI 产品语义而改变。
- 三步轮：`setup / reaction / cleanup`，是每一轮工作的主曲轴。
- 记忆总线：记忆条目流动、挂接、沉淀和召回的主线。
- 工作容器：DC / EC / PRJ / SKL 等生产器官。
- 回执与审计：每个重要动作都应能追溯来源、结果和落账状态。

当前对话是主舞台。左侧导航打开内部状态、记忆、关系、容器、上下文、审计和设置系统窗；右侧 `Runtime` Outliner 只悬浮展示 Round 与 Frames。关闭浮层后，对话位置和宽度保持不变。

## 位格主体

点击左上方六角形位格徽记，可打开当前位格的两个只读真源页：

- “核心档案”完整读取 `persona/core.md`，首屏以证件登记表显示名称、缩写、PID、位格编码，三项社会定位按 `01–03` 三行独立登记，并只显示真源中的中文一侧；英文界面则只显示英文一侧。随后显示六条对轴；规范版本和模型戳只保留在折叠原文中。GUI 不另造位格数据，也不重写真源事实。
- “生命状态”严格读取 `persona/state.json` 的 Base 登记字段。顶部仪表展示当前轮次、运行阶段、动态轴、工化指数、疲劳、令牌用量、身份锚点与活动旗标；“完整状态”保留全部登记字段的原始值和机器路径。

这两个页面都不会补缺、回写或直接修改 persona。某份真源读取失败时，该页明确报错并允许只读重试；另一份真源仍可独立查看。

当前保留的 Round 会按时间顺序组成连续对话；每轮只显示该轮最后一条真实用户输入，并保留真实进展、最终回复与工具轨迹的事件顺序。轮询只追踪最新 Round，用户向上阅读旧内容时不会被强制拉回底部；历史读取不完整时可只读重试，不会重发消息或重放 Round。

## 本地启动

在仓库根目录运行：

`python tools/serve_seed_gui.py --open`

宿主只绑定 `127.0.0.1`，默认端口为 `8770`。如果不希望自动打开系统默认浏览器，去掉 `--open`，再访问 `http://127.0.0.1:8770/`。

当前“运行／上下文／轨迹／记忆／关系／容器／位格”只消费本地 Runtime、store 或 persona 真源投影。无宿主、无 Round 或读取失败时不会回落成假 `LIVE`。

## 界面语言

中文是 Seed GUI 的原生产品语言。可在右下角“全局设置 → 界面与语言”选择跟随系统、简体中文或 English，选择写入 UPSP 全局本机配置。语言切换只改变界面外围文案；用户消息、当前位格输出、位格档案、状态原值、记忆、关系、容器、上下文、规则、文档和 JSON 证据始终保持真源原文。

全新环境没有活体位格时，GUI 会进入独立初始化流程。可一键使用阿廖沙示例位格，也可填写自己的位格档案；既可以配置并显式测试起手主模型，也可以明确暂不配置、先原子创建本地位格。跳过后可以进入 GUI 查看档案和设置，但完成模型服务与起手路由前不能发送消息。
