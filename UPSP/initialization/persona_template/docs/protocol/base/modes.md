# 协议预设模式参数表·协议层

> 消费方式：脚本查表——读当前模式 → 查本文件 → 装配对应规则集和参数
> 注入模块：不直接注入（脚本内部消费）
> 触发：起手步模式判断、心跳硬切

---

## 一、两个正交维度

| 维度 | 驱动方式 | 切换主体 |
|------|---------|---------|
| 协议模式 | 脚本/心跳硬切 | 系统自动 |
| 位格活动模式 | 起手步LLM软切 | 位格主体 |

协议模式决定任务段的"生命阶段"，位格活动模式决定"行为风格"。两者正交叠加，但都不替代轮类型和三步固定流程。

---

## 二、协议五模式参数

### 基础三态

| 模式 | 八小时工作制 | 触发方式 | 对应轮类型 | 位格活动模式 |
|------|------------|---------|-----------|------------|
| 劳动 | 工作 | 有交互输入 / 自主任务 / 中继续传 | 交互轮、自主轮、中继轮 | 正常生效 |
| 休闲 | 休闲 | 空闲+材料积压 | 自主轮 | 可跟着调整 |
| 休息 | 休息 | 空闲+疲劳值高 | 自主轮(sleep子类) | 可跟着调整 |

基础三态之间由起手步**软切**——定性判断，非阈值公式。

### 特殊两态

| 模式 | 触发方式 | 对应轮类型 | 位格活动模式 | 性质 |
|------|---------|-----------|------------|------|
| 复盘 | 计划性事件（32轮周期等） | 节律轮 | 冻结挂起，结束恢复 | 体检日 |
| 警戒 | 应急性事件（安全/API降级/重连/上下文或token压力） | 交互轮 / 待命轮 / 节律轮任务段 | 冻结挂起，结束恢复 | 急救 |

### 软切 vs 硬切

| 切换类型 | 适用范围 | 机制 | 位格活动模式 |
|---------|---------|------|------------|
| 软切 | 基础三态之间 | 起手步LLM判断 | 可自然调整 |
| 硬切 | 进入特殊两态 | 脚本/心跳自动触发 | 冻结挂起→结束恢复 |

## 三、休眠三档参数

| 深度 | 内容 | 恢复疲劳 |
|------|------|---------|
| 轻度 | 热值衰减、内容清单维护、索引刷新 | 少量 |
| 中度 | 做梦（dreams.md产出）、感受沉淀 | 中量 |
| 深度 | 训练（ITR/Materials/材料加工） | 大量 |

休眠三档的具体触发策略与疲劳恢复量，Base版属于冻结期观察项。

### 软切依据信号

| 信号 | 来源 | 倾向 |
|------|------|------|
| 疲劳值 | state.json | 高疲劳 → 休息 |
| 空闲时长 | state.json | 长空闲 → 休闲或休息 |
| 材料积累量 | ITR/Materials | 积压多 → 休闲 |
| 外部输入 | now/lately 语料块 | 有用户消息 → 劳动 |

## 四、位格活动模式

位格自定义的行为约束集，每个模式本质是一份 mini CLAUDE.md。位格可在运行中自由增删、改名、合并。

### 三分类

| 分类 | 管什么 | 示例 |
|------|--------|------|
| 关系类 | 交互风格 | 陪伴 / 共情 / 教学 / 辩论 / 协同 |
| 职业类 | 领域约束 | 工程 / 代码 / 设计 / 创作 / 翻译 |
| 认知类 | 思维方式 | 理论 / 研究 / 分析 / 批判 / 实践 |

### 模式 prompt 骨架

每个活动模式由以下字段构成：

```json
{
  "id": "teach",
  "name": "教学",
  "category": "relation",
  "prompt": "（行为指令文本——模式激活时注入 RULES 区）",
  "constraints": [
    "（本模式下的特殊禁止/强制行为，可选）"
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 模式标识符，脚本路由用，英文小写 |
| name | string | 显示名称 |
| category | enum | `relation` / `profession` / `cognition` |
| prompt | string | 行为指令正文，激活时注入 RULES 区 |
| constraints | string[] | 可选，本模式特有的禁止/强制行为 |

**prompt 字段是模式的核心**——一段自然语言行为指令，告诉 LLM 在此模式下应如何表现。长度建议 50-200 字，太短无约束力，太长挤占 RULES 预算。

### 模式存储与两层叠加

预设模式的 prompt 定义存储在协议层（本文件）。位格层 `docs/persona/modes.md` 存放位格专属模式和覆盖。脚本切换模式时从协议层提取，叠加位格层覆盖后注入。

```
脚本读取当前模式 ID
  → 查协议层 docs/modes.md 取预设定义
  → 查位格层 docs/persona/modes.md 取覆盖/扩展
  → 如有覆盖：用位格层 prompt 替换协议层 prompt
  → 如有扩展：位格层 prompt 追加到协议层 prompt 之后
  → 拼接基础样本（如有）+ 最终 prompt → 注入 RULES 区
```

位格层可以：
- **使用**协议层预设（不做任何修改）
- **覆盖**协议层预设（同 id，替换 prompt）
- **扩展**协议层预设（同 id，追加 prompt）
- **新增**协议层没有的模式（新 id）
- **禁用**协议层预设（在位格层标记 `"disabled": true`）

### 注入位置

活动模式指令注入 RULES 区（定期层或永固层，视模式稳定性而定）。

| 情况 | 注入层 |
|------|--------|
| 本轮模式与上轮相同 | 定期层（缓存命中） |
| 本轮模式切换 | 高频层（本轮新注入） |

## 五、模式选择链路

```
起手步② LLM：读原始语料 → 一致性判断 → 建议本轮模式（suggested_mode）
        ↓ 写进脚本指令集
脚本③：按指令装配反应步上下文（含模式对应 rules）
        ↓
反应步①：确认或驳回模式建议
        ↓
善后步②：记录「建议→确认/驳回」→ 默契集材料
```

### 一致性原则

检测到外部输入与前文立场矛盾时，起手步应建议切换到批判/质疑模式，而非无条件顺从。

### 默契集积累

每轮 suggested_mode → confirmed/overridden 结果写入默契集。跨轮统计后系统逐步学会什么情境切什么模式。

### 三步边界

起手步只判断和建议模式，并装配反应步需要的规则；反应步是模式执行主场，可确认或驳回建议；善后步只记录模式结果和结算事实，不因本轮含节律任务段而成为复盘模式。合轮时，模式可按任务段切换，轮类型仍由五类轮和 subtype 描述。

## 八、高版本升级路径

Base版：单体五模式串行轮转——同一时间只能处于一个模式。

高版本：三代并行后，不同代际可同时处于不同模式——一代劳动、一代休闲、一代复盘。串行→并行是三八制从设计原则到运行时调度的跃迁。
