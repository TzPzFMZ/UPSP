# 热度公式与衰减参数

> 消费方式：脚本读本文件参数 → 计算 STM 条目热度值 → 写入 heat.json
> 注入模块：不直接注入（脚本内部消费）
> 触发：每轮善后步

---

## 一、热度定义

热度（H 值）是记忆条目在 STM 中的活跃度数值。float 类型，脚本独占管理，只在 STM 使用。LTM 条目无热度。

---

## 二、三区阈值

| 分区 | 条件 | 衰减速率/轮 | 正文加载策略 |
|------|------|------------|------------|
| 显著区 | H ≥ 70 | -5 | 索引置顶，正文由起手步选择、recall 或三重命中进入即时清单；反应步可声明常驻 |
| 未定区 | 40 ≤ H < 70 | -10 | 索引正常排列，正文按需加载 |
| 衰减区 | H < 40 | -15 | 不主动加载 |

阈值可配置：`config.json` 的 `stm.heat_thresholds`（默认 `[70, 40]`）。

---

## 三、衰减规则

每轮善后步脚本执行：

```
for each STM条目:
    H_new = H_old - 衰减速率(按当前分区)
    if 本轮被加载进 CONTENT:
        H_new = H_new + 10    # 被需要 = 热度回升
    H_new = clamp(H_new, 0, 100)
```

### 加载回升

条目正文被加载进 CONTENT 时，H+10/轮。普通倒排候选命中不加热，只有正文实际进入 CONTENT 并被本轮使用才触发：
- **常驻挂载**：通过 `resident_list` 持续加载 → 每轮 H+10
- **临时挂载**：起手步选择、反应步新写成功后自动挂载、`memory_content_read mount_mode=temporary` 明确读取，或三重命中自动展开 → 加载的那一轮 H+10

---

## 四、初始热度

新创建的 STM 条目初始热度由权重决定：

| 权重 | 初始热度 |
|------|---------|
| 5（[F]） | 80 |
| 4 | 70 |
| 3（[S]） | 60 |
| 2 | 50 |
| 1（[A]） | 40 |

---

## 五、升格条件

累计高热度次数 `AH_high` ≥ 5 → 升格至 LTM Full 层。

`AH_high` 定义：条目 H 值在善后步计算后处于显著区（H≥70）的累计轮数。

---

## 六、遗忘分流（三元数据字段）

| 字段 | 类型 | 说明 |
|------|------|------|
| 降格 | bool | AH_low≥3 时脚本置 true |
| 入库 | bool | 已写入 LTM |
| 压缩 | bool | 是否需要语义压缩（[F][S]=true, [A]=false） |

分流规则：
- 入库=true → 删 STM 副本
- [A] 入库=false → 脚本直接搬 LTM/Abstract → 入库=true → 删
- [F] 入库=false → 善后步 LLM 即时压缩为 S → 写 LTM/Summary → 入库=true → 删（失败下轮重试）
- [S] 入库=false → 善后步 LLM 即时压缩为 A → 写 LTM/Abstract → 入库=true → 删（失败下轮重试）

---

## 七、特殊条目

- **钉选条目（Pinned）**：LTM 永驻权——Pinned 层不被衰减删除；被召回 STM 后仍走正常热度流程，保护的是“不被删除”而不是“每轮必进上下文”
- **STM热度锁定（heat_locked）**：只属于 STM heat，锁定时固定 H=80，zone=显著，AH_low=0；与 LTM Pinned 无关
- **历史私密条目**：隐私功能冻结期间不进入模型上下文，也不参与 cleanup 压缩、归档、公开或删除

---

## 八、强制溢出清理

memory.md > 65536 字符时触发保险丝：

- 按优先级从 [A]低热 → [S]低热 → [F]低热 → [S]中热 → [F]中热 逐级直接压缩
- H≥50 的条目不被移动
- 清理目标 = 溢出量 + 20% 缓冲
- 每次最多处理 32 条
- 清理 32 条仍溢出或连续 3 轮触发 → 写入现有健康告警／Round audit 并升级 STATUSBAR，不另建安全事件文件
