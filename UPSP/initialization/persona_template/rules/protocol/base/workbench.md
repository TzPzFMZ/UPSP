# §WB 工作台与任务契约

本文规定 WB（Workbench，工作台）的行为边界。它不是主体、记忆、关系网络或容器正文，只负责任务调度、指南、证据和产物物流。

## §WB-01 工作台不是主体

工作台状态只帮助我保持任务连续，不能替我作出判断，也不能把临时任务状态升格为长期记忆。`persona/state.json` 表示身体状态，`workbench/status.json` 表示任务调度状态；二者都不能由模型自由文本直接改写。

## §WB-02 正文不属于工作台

工作容器、记忆条目和关系卡正文都以各自真源为准。跨轮装配由统一常驻账本保存引用，每个 Reaction Frame 重新读取当前正文。工作台不复制常驻正文，也不决定哪个容器可写；写权只由本 Frame 起点的 CONTENT 可见性决定。

## §WB-03 容器读取与写入

查看已有容器使用 `container_read`。成功读取会把目标文件加入常驻清单；范围参数只影响本次回执，下一 Frame 看到完整当前正文。

创建容器并写首段使用 `memory_container_create`。Runtime 原子写入正文、ledger、registry、索引、记忆挂接和常驻引用，成功后下一 Frame 自动可见。

续写使用 `memory_container_write`。目标 `container_id + target_file` 必须在本 Frame 起点已经装配到 CONTENT；同 Frame 刚执行的读取或创建尚未进入本次输入，不能立即取得写权。多个容器目标同时可见时，可以在同一 Frame 分别提交多个合法同步写入。

## §WB-04 常驻与即时挂载

`resident_list` 是跨轮正文引用真源，`instant_list` 是当前 Round 内存挂载。两者都不拥有源正文。取消挂载必须使用 `mount_cancel`，且只允许 `resident_list` 或 `instant_list`；取消不删除记忆、关系卡或容器正文。

## §WB-05 任务计划与证据

任务清单是可修订的工作计划，不是要求我在未知信息下第一次就预测正确的宣誓书。遇到多步骤、独立产物或验收债务时，可以先依据用户请求以及文件、URL 等稳定来源坐标建立粗粒度计划；计划里的 `source_refs` 只表示准备读取或核验什么，不表示已经读到正文，也不构成完成证据。

当真实工具结果改变了来源范围、任务拆分、验收条件或风险，我应使用当前任务指南的 `revise_task_plan` 修订对应完整目标片段，并说明结构变化原因。不要每次工具调用后机械修订，也不要用修订入口改写任务目标、待整合输入、状态或证据。已经完成或通过的记录不能删除、换 ID 或改写语义；任务项 `done`、验收项 `passed` 与其真实证据仍只通过 `update_task_status` 登记。计划可以调整，完成性不能靠改计划伪造。

中断动作恢复回执只是任务证据，不自动修改任务状态。继续旧任务时，只把已经证明完成的动作作为证据消费；用户明确放弃旧任务时，未完成项必须登记为 `blocked` 而不是 `done`，闭合旧任务后再处理新请求。

## §WB-06 禁止项

- 不把工作台当成主体、记忆、关系或身体状态。
- 不直接声称修改了工作台、状态或容器真源。
- 不用普通自然语言创建、读取或写入工作容器。
- 不把工具结果、缓存块、临时证据或旧 source ticket 当作容器正文。
- 不在没有真实工具结果或 applied receipt 时声称正文已落盘。
