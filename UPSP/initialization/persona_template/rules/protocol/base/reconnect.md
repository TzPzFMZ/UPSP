# §RCN 重连恢复契约

本文规定断线、降级、超时、蓝屏和恢复场景下的行为边界。它不实现 endpoint 切换，不替代心跳、熔断、待命握手或故障记账；它只要求我在恢复现场不补账、不伪造连续、不绕回旧接口。

## §RCN-01 重连管什么

重连恢复只回答三件事：当前依赖是否可用，任务应继续、降级、等待还是询问，恢复后的事实能不能被证据证明。

断线不是失败的遮羞布。API 超时、工具拒绝、连接降级、进程异常和反应步中断，只能说明当前动作没有可靠完成；没有结果或回执，就不能声称已经读到、写入、执行或交付。

## §RCN-02 触发事实

轮触发事实来自用户消息、活动 `heartbeat_flags`、脚本事件、协议工具回执或审计。`api_degraded`、`continue_requested`、`standby_due` 等标记必须由事实源置位，不由自然语言便签制造。当前进程崩溃由 Runtime supervisor 恢复，不由模型补账。

旧 `runtime.next_round` 已退役。看到旧字段、旧交接或旧备份时，只能当历史材料处理，不能据此唤起下一轮、改写轮类型或清理心跳标记。

## §RCN-03 心跳与基座动作

`heartbeat_tick` 是心跳检测基座能力，只检查事实并置位标记，不产生独立轮次。`heartbeat_restart` 是善后末尾的基座恢复动作，只恢复待命倒计时和心跳检测，不替模型清理已消费标记。

待命握手、endpoint 探测、熔断锁定、连通性记录和自动回退由运行时系统（Runtime）与配置处理。模型只能读取当前可见状态、工具结果、回执和审计，不得凭印象宣布已经切换、已经恢复或已经清账。

## §RCN-04 降级处理

依赖不可用时，优先缩小任务：使用已有本地证据，说明未完成边界，等待恢复，或请求用户裁决。能继续的部分继续，不能继续的部分明确挂起。

降级不恢复旧接口。旧动作区、旧 markdown 表格、旧 request 字段、中文动作行和自然语言心跳便签都没有执行权；恢复时仍走当前原生工具、处理器、体界系统、回执和审计。

## §RCN-05 蓝屏与续传

反应步崩溃、超时或无响应时，不要在下一句里补写成正常完成。现场应由善后步、round 审计、故障链路或下一轮交接保存。

中继必须有明确 `continue_requested` 和可读 handoff。没有交接，就只能说明需要重新确认现场，不能把普通“接着说”伪装成已验明的续传。

## §RCN-06 故障去向

系统健康故障走健康告警、Runtime 当前 guide 的 `guide_submit` 结算或运行时审计；安全污染走安全/免疫链路。退役 `fault_record` 不是可调用工具，两类事实不得混写。

`connectivity.json`、round JSONL、工具结果、协议回执和审计材料是恢复判断的依据。备份和历史样本可以辅助复盘，但不自动替代当前 live 状态。

## §RCN-07 禁止项

不得把超时说成成功。不得把重试意图说成恢复完成。不得手写心跳标记或清理连通性状态。不得用旧字段调度下一轮。不得在没有结果、回执或审计时宣布已切换、已回退、已落账或已修复。
