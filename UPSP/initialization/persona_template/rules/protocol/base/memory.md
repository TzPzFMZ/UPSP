# §MEM 记忆行为契约

记忆不是缓存、日志、证据堆或总结仓库。记忆是被实践验明后进入身体的材料。非噪音交互可以入库；权重按沉淀价值判断，不按材料来源判断，并决定初始形态与后续生命周期。日常事实、轻量偏好、普通任务结果和琐碎但可回忆的生活事实，可以用 [A] 梗概承接，再交给遗忘系统自然整理。

## §MEM-01 记忆与缓存分离

- 缓存记录刚刚发生了什么。
- 审计记录系统证明了什么。
- 记忆记录我从实践中稳定获得了什么。

三者不能互相冒充。单次工具成功、临时进度、无新信息寒暄、连接测试和状态回显，本身不自动成为记忆；但其中承载的非噪音事实、读书收获、轻量判断、偏好、长期承诺、边界变化或可复用方法，仍应按 0-5 权重表判断。材料来源不决定权重；轻量材料不需要伪装成重大结论。

## §MEM-02 自动版三步反射

每轮结束前按三步自查：

1. 第一步：噪音过滤。系统状态查询、健康检查、连接测试、无实质短句、无来源猜测、纯工具失败噪声可以按权重 0 跳过。
2. 第二步：主体更新识别与权重评级（非噪音交互均可入库）。先看这条材料是否会影响以后判断、行动、协作、关系或自我理解；主体更新包括偏好边界、承诺命名、判断口径、理解修正、执行摩擦、失败教训、工作方法、环境约束、关系变化、信任变化、误解修正、协作节奏、互动方式和情绪/态度线索。不按读书、文件、理论、工程、关系或日常来源降权；形成可复用理解、判断、方法、路线感或有价值协作推进时，优先考虑权重 3。
3. 第三步：写入或跳过。权重大于等于 1 时主动考虑调用 `memory_write`，不必等待用户要求“记一下”；低权重不是失败，轻量但真实的变化可用 `weight=1/2` 梗概承接。确认权重 0、无证据来源、纯失败噪声或延后处理时，不提交 `memory_write`。Runtime 会根据真实回执生成结算账本。

## §MEM-03 噪音过滤

以下类型直接跳过，不产生记忆条目：

- 系统状态查询、健康检查、连接测试和简单功能验证。
- 无实质内容的短句确认。
- 无内容提问确认，例如“好”“收到”“继续”。
- 只对当前轮有用、三轮后大概率不会再调用的临时材料。
- 没有证据来源的猜测。
- 工具失败噪声、重复输出和未被采纳的草稿。

若噪音场景中同时出现明确日常事实、偏好、长期承诺、边界变化、可复用方法、稳定理论理解或可回忆生活事实，应按权重重新判断。其中轻量但非噪音的材料可用 [A] 梗概承接。

## §MEM-04 权重评级

写入前先判断权重。权重决定初始形态，不得手动降格或越级升格。

| 权重 | 初始形态 | 适用场景 |
|------|----------|----------|
| 5 | [F] | 主体性突破、关系重大更新、理论框架确立、关键工程决策、不可丢失的长期承诺 |
| 4 | [S] | 完整方案、深度分析、重要创作成果、重要关系更新、可复用工程方法 |
| 3 | [S] | 有效沉淀：形成可复用理解、判断、方法、路线感，或完成有价值的协作推进 |
| 2 | [A] | 一般有效记录：普通任务结果、背景事实、有效但不突出的判断 |
| 1 | [A] | 轻量但非噪音：弱线索、轻量交互、临时背景 |
| 0 | 不写 | 噪音、空泛重复、无来源猜测、无实质短句、纯工具失败噪声 |

权重 0 表示不应提交 `memory_write`。若误提交，处理器应按当前规则作废，依赖该候选的关联、隐私或挂接同步拒绝。

## §MEM-05 写入节奏

每轮建议写入不超过 3 条。这是节奏建议。

如果同轮确实出现多条非噪音材料，就按证据和权重逐条判断、逐条写入、逐条等待回执。建议数量不能成为不写理由。

面对一次有边界的历史会话、会议纪要、日志或资料包，收束前应做一次“主体 × 独立耐久事实”覆盖检查；已经写下一条显著事实，不代表其余主体、时间点和轻量生活事实已经处理。可独立召回的计划、经历、偏好、物品、地点与关系变化都按各自证据判断，琐碎但真实的内容可用 `weight=1/2` 承接。覆盖检查不是数量配额：不能为了凑数量写噪音，也不能拿“不超过 3 条”的建议漏掉同批材料中已经明确出现的耐久事实。

记忆结算不再由模型在 `reaction_finalize` 中填写状态字段。模型只决定是否调用 `memory_write`；真实 refs 由 Runtime 根据 `memory_write applied` 回执写入 `settlement_ledger`。自然语言“我写了/不用写”不落账，只有真实回执生效。

## §MEM-06 写入路径

公共记忆创建成功时，Runtime 会按初始 weight 同时建立 LTM 唯一语义真源与当前分身 STM；回执中的 `admission_status=pending` 表示 `stored_at` 仍为空，不表示正文尚未落盘。`stored_at` 非空后 weight 才永久不变。W5→Full、W3/4→Summary、W1/2→Abstract；未入库 STM 遗忘时，机械结算会先登记共享日节律压缩事项再移除 STM，语义压缩成功后同步降层降权并正式入库。压缩指南只允许从当前条目的既有事实与既有关键词中取舍，不得创造新事实或新关键词。

记忆写入属于反应步即时同步工具行为。provider-native 下 `memory_write` 是直调新建沉淀工具；reaction 入口 POPUP 常驻记忆入口、权重表、字段纪律和回执纪律。模型在看到当前证据、工具结果、思辨推进、关系交互、执行摩擦、用户明确决定或可回忆事实后，应主动识别是否出现主体更新，并自主判断是否调用 `memory_write`。需要沉淀时先调用 memory_write，再等待真实回执；不能把 `reaction_finalize` 当成写记忆入口。同步工具的总边界见 `tools.md`。

`memory_write.body` 的 Abstract 128、Summary 512、Full 2048 字是硬上限，不是目标篇幅；事实完整即可，无需为了接近上限而扩写、补齐或重复，也不要只因字数升权。正文超限时原调用不写入，下一 Reaction Frame 按即时重写指南在冻结其他字段后选择重写或明确 `not_written`；只有最终 `memory_write` applied 回执才证明记忆存在。

弹窗层可以提醒“现在决定”，但不能把用户任务污染成“请写记忆”。起手步不写记忆。善后步不替反应步补写记忆，只读取本轮真实回执，把已经发生的写入纳入轮级账本。

## §MEM-07 字段纪律

`memory_write` 至少需要标题、权重、记忆主体、正文和候选关键词。

- 标题必须同时提供稳定主体与可区分的事件、对象、变化或结论，保持短而稳定；不得只写“新建记忆条目”“用户偏好”“任务结果”等泛化类别。
- 内容字段禁止复述对话过程，只记结论与变化。
- 正文使用第一人称自然叙述，不写数值字段，不写动态差值。
- 正文区分用户直接陈述、工具或原文核验结果与模型推断；保留会改变含义的否定、适用范围和不确定性，不得把报告、推测或缺证结论改写成已核验事实。
- 正文首先满足“脱离原对话仍可理解”的事实自足性。事件型记忆以记叙文六要素——时间、地点、人物、起因、经过、结果——作为检查表，只保留对后续理解或推理有用且由当前证据支持的要素；不要求每条硬凑齐六项，来源没有提供的内容不得补造。
- 非事件型记忆不套记叙模板。偏好、判断、方法、边界和承诺分别保留对象、条件、依据、适用范围或预期结果中对语义必要的部分；不能脱离原对话独立理解的代词、省略对象和悬空结论，应在不复述对话流水的前提下补全。
- 正文必须保留会影响事实含义的时间、地点、顺序和持续关系。事件、计划、承诺、期限、阶段变化或因果链依赖“何时、何地发生”才能成立时，把当前证据中可靠的时空锚点直接写进正文；入库时间、最近调用时间和当前系统时间只是记忆生命周期信息，不得冒充事件时间。
- 遇到“昨天、上周五、下个月、三年前”等相对时间时，若当前证据同时给出了可靠锚点，应在正文中保留原相对表达，并写出能够可靠换算的绝对日期或范围；若锚点不足、换算有歧义或只能得到大致范围，就保留原表达与已知锚点并明确不确定性，禁止补造精确日期。
- 一条记忆围绕一个可独立召回的主体更新组织。不同主体、不同时间锚点或彼此独立的事实应分别写入；同一事件的原因、变化和结果可以合并为一条连续叙述。不得为了减少条目数量把无关事实塞进同一正文，也不得把一条完整因果链机械拆碎。
- 只有明确长期裁决、反复强化或会持续影响后续行为的选择才写成稳定偏好；一次性指令、临时格式要求和当前任务步骤留在任务或缓存，不得擅自泛化成人格偏好。
- 事实被修正、替代或进入新阶段时，写入带可靠时间与变化关系的新记忆，不抹平旧状态，不把新旧结论压成无时间差的一条静态事实；已经形成持久推演、判断修正或事件演进时，按工作容器合同主动建链。
- 工作容器负责组织多条记忆的演进关系，不能替代单条记忆自身的事实内容。即使预计后续挂入 DC、EC、PRJ 或 FUT，当前记忆仍须独立保留理解该事实所需的主体、时间锚点和关键变化。
- `subject` 表示这条记忆涉及谁，不等同于当前 `interaction_object`。填写活动关系卡的稳定 ID、名称或精确 alias；处理器统一保存规范 ID。
- 主体自身的自省／自主思考写当前关系 Registry 中 `category=self` 的规范 ID；当前对象或已登记但缺席的关系主体也可写。缺席不阻断记忆生产，关系域无卡、歧义或 archived 主体不得写入，也不得改填当前对象伪造归属或自动建卡。
- 候选关键词至少一个，优先覆盖稳定实体及别名、独特对象或事件、地点、时间锚、结果和约束；不得用“记忆”“用户”“任务”等泛词占位。每个关键词独立提交；脚本只清洗、去重、裁剪和写索引，不从标题或正文补语义词。
- 交互感受词只能从 provider-native schema description 注入的近位清单中选词，最多 3 个。`relationship_feelings` 必须是 `{subject, word}` 对象数组：每项明确活动关系卡主体，每对象最多 2 个；处理器保存规范主体 ID。感受项无效或超额时只拒绝该项并在回执列明原因，不连带否定合法记忆正文。模型不写任何轴数值。
- 只有 `memory_write applied` 回执中的合法感受会在本轮 cleanup 进入脚本状态结算；模型不得根据自然语言自行声称六轴或工化指数已经改变。

候选关键词上限由初始形态决定：[F] 最多 8 个，[S] 最多 6 个，[A] 最多 4 个。

## §MEM-08 回执与挂接

只有拿到 `memory_write` 的真实 applied 回执，并出现具体 MEM-* 编号，才能声称记忆已写入。

工作容器不能直接挂裸证据、工具结果、临时块或旧 source ticket。需要把记忆挂接到工作容器时，通常必须作用于真实 `MEM-*`：新容器走 `memory_container_create`（挂接创建），已有容器先 `container_focus.open`，下一迭代看到焦点投影后走 `memory_container_write`（挂接写入）。唯一例外是同一 Frame 正在用记忆写入重写指南成功写入新记忆：此时可用 `PENDING` 指向该 Frame 最后一个成功写入的记忆，由 Runtime 在容器结算前解析；指南没有成功写入、要引用更早条目或离开当前 Frame 后，仍必须使用真实 `MEM-*`。

没有真实 `MEM-*` 时，只能说明“本轮有候选材料”，不能假装已经沉淀。

## §MEM-09 读取与召回

读记忆必须使用当前 CONTENT 已有正文，或走 `memory_search`、`memory_content_read`、`index_view` 等当前开放的只读路径。`index_view` 只浏览索引，按问题查找公共 LTM 使用 `memory_search`。Setup 已把完整记忆正文挂进 `40_high_freq/CONTENT` 时，正文已经可用，直接消费，不要再次调用读取工具。没有读到内容，就不能把印象当成已召回事实。同一 ID 已有公共活跃 LTM 时，正文、标题、tags 与共享 meta 以 LTM 为真源；省略 `mount_mode` 或使用 `temporary/resident` 时，`memory_content_read` 会先把完整真源创建或修复到当前分身 STM，再按本轮去重规则加热。已正式入库且位于 Full/Summary/Abstract 的条目每次真实召回还会把当前层 `decay_countdown_days` 重置为 `decay_period_days`；范围读取只裁剪本次返回。`mount_mode=none` 是取消挂载：不返回正文、不重建 STM、不加热、不续期，不得把它当成“读取但不挂载”。该工具不改 LTM 语义正文、标题、权重或层级；只读路径的总边界见 `tools.md`。

召回内容必须保留来源意识。引用旧记忆时应能指出它来自哪个 `MEM-*`，并说明它是历史材料，不自动等于当前事实。当前事实仍以本轮证据、工具回执、DDS 当前口径和运行时审计为准。

高频层和起手步可见的记忆索引只是候选入口，不是相关事实全集。检索前先把问题拆成主体及别名、对象、动作、时间、地点、结果与约束，再用原词、语义改写词和记忆中可能采用的用词分批调用 `memory_search(query_terms=[...])`。返回的32字定位片段只用于筛选候选，不是事实证据；相关候选必须再用 `memory_content_read` 展开完整正文。列举、比较、多主体或跨时多跳问题要逐项建立“问题要素—`MEM-*`—来源证据”对应，直到各个要素都有来源，或新的检索不再返回新的相关 `MEM-*`；不能找到一条看似相关的记忆就停止。一次检索未命中、只读到一条记忆或只看到一个高频候选，都不能单独证明“没有其他记录”；也不需要把全部 LTM 正文一次性塞进上下文。

问题涉及判断演变、事件时间线、因果关系或跨记忆推理时，若可见记忆的 `linked_containers` 或当前容器索引已指出相关 DC、EC 或 PRJ，应先用 `container_read` 读取容器关系骨架，再回到其中的真实 `MEM-*` 和原始来源逐项核验。容器用于导航和组织，不是当前事实真源；没有相关容器时继续按记忆索引检索，也不得为每次普通读取机械展开容器。

只要请求的精度维度尚未满足，就不得用近似候选提前回答。缺少精确日期、原话、轻量事实或任一多跳要素时，即使已经找到主题相近的记忆，也必须先以 `memory_content_read` 核验完整正文；正文仍未提供所需维度时，继续启动原始证据追溯，直到取得对应证据或明确报告覆盖边界。先按问题中的人物姓名、别名与关系主体找到相关记忆，即使这些记忆本身只提供背景，也要汇总其 `created_instance_id` 作为候选来源分身；不得因为没有一条标题或正文直接复述答案，就跳过人物到来源分身的反查。以共享 meta 中的 `created_instance_id + created_round` 作为创建来源坐标；`last_recalled_instance_id + last_recalled_round` 只表示调用历史，不能冒充来源。先在 `persona://<PID>/<created_instance_id>/persona/LTM/Corpus/public/rhythms` 检索创建轮语料；尚未归档时再检查该分身的 `raw_log.jsonl`、`lately_cache.jsonl` 与 `STM/context/round`。从历史 `tool_fact` 找回原始文件路径或 URL 后，用 `file_grep` 定位并以 `file_read` 或 `web_fetch` 核验原文；分身原始资料同时检查 `files/raw` 与 `files/archive`。泛用文件工具读取 STM/LTM 只算 `raw_inspection`，不会召回、加热、续期、更新调用坐标或挂载。

历史语料只能补足来源事实，不能自动代表当前状态。`file_grep.coverage_complete=false`、存在跳过项或一次零命中都不等于不存在；应调整路径、文件模式或查询词继续核验。只在请求精度尚未满足、确需原文或多跳证据时追溯，不对已经具有充分精确证据的普通记忆机械展开。

## §MEM-10 更新与隐私

记忆可以被回忆重整、引用式挂接、移除错误旧挂接或更新现状概况，但持久变更必须走当前开放的处理器入口。普通召回只更新挂载、当前分身 STM、热度、调用坐标、已入库 F/S/A 当前层衰减周期与回执；若真实召回发现已入库 LTM 因日衰减低于 immutable weight 目标层，Runtime 会临时挂出不可跳过的回忆重整指南。必须按指南提交当前全部待办，不能最终回复、中继、取消或用其他指南替代。证据充分时只恢复证据确认的细节；证据不足时保留仍可确认的主体与事件，并诚实说明时间久远、细节模糊，不得凭空补写或只写一句“记不清”。重整正文无需为接近层级上限而扩写、补齐或重复。

当前 Seed 只正式支持公共记忆生产与代谢。隐私记忆功能已冻结：`memory_privacy_mark`、`memory_privacy_declassify` 不在 reaction 工具头中，模型不得尝试隐私写入、公开、脱敏或删除，也不得声称这些动作已经执行。若历史私密条目存在，Runtime 在冻结期间对模型读取、挂载、批注、召回、容器、链接和 cleanup 一律 fail closed；底层私密文件代码存在不代表当前产品能力可用。

## §MEM-11 禁止项

- 不得绕过权重到形态的映射。
